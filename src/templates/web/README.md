# Web application template "default"

A small starting point for generated web applications: a Node http server without framework, the
`pg` driver as the only dependency, list pages with edit dialogs rendered from plain entity
descriptions, an app shell with left navigation, and an English and German user interface.
No build step: what is in `public/` is what the browser gets.

## How a generated application uses it

The tool copies this folder and replaces the placeholders named in `template.json`:

| Placeholder | Meaning | Used in |
|---|---|---|
| `{{APP_NAME}}` | name of the application | `public/index.html`, `app/config.js`, `package.json` |
| `{{DB_ENV}}` | name of the environment variable with the connection string | `app/config.js` |

After that the application owns the files in `app/`, `public/pages.js` and
`public/i18n/app-*.json`. The other files stay as they are, so that a newer template can be
copied over them:

```
server.js              entry point; reads app/, starts the server on 127.0.0.1
lib/core.js            routing, JSON bodies, static files, errors, messages, pool, transactions
lib/entity.js          entity descriptions -> JSON API with parameterised SQL
public/index.html      app shell
public/app.js          front end: languages, navigation, lists, dialogs (window.App)
public/style.css       design tokens and components (see STYLE.md)
public/i18n/en.json    texts of the template, English (canonical)
public/i18n/de.json    texts of the template, German

app/config.js          name, connection string from the environment, port
app/entities.js        the entities
app/routes.js          routes beyond the entity API
app/schema.sql         table of the example entity
public/pages.js        custom pages
public/i18n/app-en.json, app-de.json   texts of the application
```

Start (Node 18 or newer):

```
npm install
node server.js
```

The connection string comes from the environment variable chosen for `{{DB_ENV}}`, the password
from that string or from `PGPASSWORD`, the port from `PORT`. The server listens on 127.0.0.1
only; put a reverse proxy in front of it for anything else. There is no login in the template.

## Adding an entity

Add a description to `app/entities.js`:

```js
{
  name: 'supplier',                 // part of the address and of the element ids
  table: 'public.supplier',         // table, optionally with schema
  key: 'id',                        // primary key column (generated by the database)
  label: 'supplier.label',          // key of the app-*.json files, or { en: 'Supplier', de: 'Lieferant' }
  labelPlural: 'supplier.labelPlural',
  icon: 'users',                    // one of the icons in ICONS.md
  orderBy: ['name', 'id desc'],
  actions: ['create', 'update', 'delete'],          // default: all three
  texts: { new: 'supplier.new', save: 'supplier.save' },   // optional button texts: new, edit, delete, refresh, save, noneSelected
  columns: [
    { name: 'id', label: 'list.id', type: 'integer', readOnly: true, inForm: false },
    { name: 'name', label: 'supplier.name', type: 'text', required: true },
    { name: 'rating', label: 'supplier.rating', type: 'text', options: ['A', 'B', 'C'] },
    { name: 'limit', label: 'supplier.limit', type: 'number', decimals: 2, min: 0 },
    { name: 'since', label: 'supplier.since', type: 'date' },
    { name: 'active', label: 'supplier.active', type: 'boolean' },
  ],
}
```

Column settings: `type` is `text`, `integer`, `number`, `date` or `boolean`; `required`;
`readOnly` (shown, never written); `options` (allowed values, shown as a select field unless
`input: 'text'`); `min`; `decimals` (digits shown for numbers); `inList: false` and
`inForm: false` hide a column in the list or in the dialog.

That gives:

- a page in the navigation with the list, the buttons and the "Selected id" field,
- the edit dialog,
- the API: `GET /api/entity/supplier`, `GET /api/entity/supplier/<id>`, `POST /api/entity/supplier`,
  `PUT /api/entity/supplier/<id>`, `DELETE /api/entity/supplier/<id>`.

All values are sent to the database as parameters, all identifiers are quoted, and a column that
is not in the description (or is read-only) is refused with status 400.

Element ids follow the names: `#nav-supplier`, `#btn-new-supplier`, `#btn-edit-supplier`,
`#btn-delete-supplier`, `#btn-refresh-supplier`, `#supplier-selected-id`, `#supplier-list`,
`#supplier-row-<id>`, dialog `#dlg-supplier` with the fields `#supplier-<column>`,
`#btn-save-supplier`, `#btn-cancel-supplier` and the status line `#supplier-status`. The status
line of the main window is `#status`.

## Adding a custom page

Server side, in `app/routes.js`:

```js
module.exports = function routes(router, app) {
  router.get('/api/report/:year', async (ctx) => {
    const result = await app.pool.query('SELECT count(*) AS n FROM supplier WHERE extract(year FROM since) = $1', [ctx.params.year]);
    return result.rows[0];
  });
  router.post('/api/transfer', async (ctx) => {
    const body = await ctx.body();
    if (!body.from) throw new app.core.HttpError(400, 'transfer.fromMissing');
    return app.core.withTransaction(app.pool, async (db) => {
      // several statements that belong together; an error rolls everything back
      await db.query('UPDATE supplier SET active = false WHERE id = $1', [body.from]);
      return { done: true };
    });
  });
};
```

A handler returns the value that is sent as JSON. Errors are thrown as
`HttpError(status, messageKey, args)`; the answer is
`{ "error": "<English text>", "code": "<messageKey>", "args": {...} }` and the front end shows
the text of the key in the chosen language.

Browser side, in `public/pages.js`:

```js
App.registerPage({
  id: 'report',
  label: 'page.report.title',
  icon: 'file-text',
  async render(container) {
    const data = await App.api('GET', '/api/report/2026');
    container.append(App.el('div', { class: 'card' },
      App.el('div', { class: 'card-b' }, App.el('p', { id: 'report-count', text: App.t('page.report.count', { count: App.formatNumber(data.n, 0) }) }))));
  },
});
```

`window.App` offers: `api(method, url, body)`, `t(key, args)`, `label(spec)`, `el(tag, attrs, ...children)`,
`icon(name, size)`, `button(id, text, icon, onClick, kind)`, `createList(options)`,
`openDialog(options)`, `setStatus(text, kind)`, `setMeta(text)`, `formatNumber(value, decimals)`,
`formatDate(value)`, `lang`.

## Languages

All texts of the user interface and all messages of the server come from the resource files in
`public/i18n`: `en.json` and `de.json` belong to the template, `app-en.json` and `app-de.json`
to the application. English is canonical; both files of a pair must have the same keys (the
tests check that). Placeholders are written as `{name}`.

- In HTML: `data-i18n="key"` sets the text, `data-i18n-title`, `data-i18n-aria-label` and
  `data-i18n-placeholder` set attributes.
- In scripts: `App.t('key', { name: value })`.
- Labels of entities and columns: a key, or an object `{ en: '...', de: '...' }`.

The language is chosen in this order: `?lang=en` or `?lang=de` in the address, the choice stored
by the switch in the navigation, the language of the browser, English. Numbers and dates are
formatted for the chosen language; every table cell carries the unformatted value in
`data-value`. Ids, element ids, API field names and log output are the same in every language.

## Tests

```
node --test
```

The tests need no database and no installed packages: routing, protection of static paths,
entity SQL including quoting and refusal of unknown columns, the HTTP handler with a stand-in
pool, and the language resources (same keys in both languages, every used key exists).
